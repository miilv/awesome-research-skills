# 01. Философия: как думать об агенте

[← к оглавлению](../README.md)

Шесть принципов. Они не про конкретную кнопку, а про то, почему у одних агент
экономит день в неделю, а у других выдаёт правдоподобную чушь.

---

## 1. Агент — исполнитель, а не собеседник

Чат отвечает текстом. Агент читает ваши файлы, запускает ваши скрипты, правит
ваш `.tex`, коммитит в ваш git. Разница не в качестве модели, а в том, что у
агента есть руки.

Практическое следствие: перестаньте копировать куски статьи в окно браузера.
Запустите агента в директории проекта и говорите «посмотри `sections/methods.tex`
и `data/raw/`». Он сам откроет, сам сверит, сам покажет diff.

Формулируйте задачи как задачи, а не как вопросы:

| Чат | Агент |
|---|---|
| «Как посчитать доверительный интервал для AUC?» | «Добавь bootstrap-CI для AUC в `analysis/eval.py`, 2000 итераций, и перегенерируй Табл. 3» |
| «Хорошее ли у меня введение?» | «Прочитай `sections/intro.tex`, выпиши все утверждения без ссылки, дай список строк» |

## 2. CLI и доступ к файлам — это и есть весь фокус

Работа идёт в терминале, в корне проекта. Агент видит дерево файлов, историю
git, вывод команд. Это даёт ему то, чего никогда не даст загрузка PDF в чат:
контекст вашей реальной работы, а не её пересказ.

Отсюда следует практика: **один репозиторий = один проект = одна сессия**.
Статья, данные, код анализа, заметки — рядом. Если данные нельзя класть в git
(тяжёлые, чувствительные), пусть они лежат рядом на диске, а в репозитории
будет `data/README.md` с описанием, откуда они и как получены.

## 3. Контекст решает

У модели ограниченное окно контекста, и всё, что в него попало, соревнуется за
внимание. Вываливать в агента всё подряд — худшая стратегия: точность падает,
деньги тратятся. Задача исследователя — собрать **минимальный достаточный**
контекст: нужные файлы, нужные куски, нужные правила.

Три рычага:

- **Постоянный контекст** — `CLAUDE.md` / `AGENTS.md`: то, что должно быть
  верно в каждой сессии. См. [02. Память проекта](../02-memory/README.md).
- **Контекст по требованию** — скиллы и правила: загружаются, когда нужны.
  См. [03. Механики](../03-agent-basics/README.md).
- **Контекст сессии** — что вы попросили прочитать здесь и сейчас.

Anthropic называет эту дисциплину context engineering — стоит прочитать их
разбор целиком: [Effective context engineering for AI
agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents).

## 4. Не верь, проверяй

Модель порождает правдоподобный текст. Правдоподобная ссылка на статью, которой
не существует, — самый частый и самый дорогой отказ в научной работе. Это не
баг конкретной модели: так устроена генерация.

Железное правило: **всё, что можно проверить программой, проверяет программа.**

- Ссылки и цитаты — через Crossref / OpenAlex / arXiv API по DOI, не «на глаз».
- Цифры в тексте — из скрипта, который их посчитал, а не из абзаца.
- Утверждение «в работе X показано, что Y» — открыть X и найти Y.

Агент здесь помогает: он умеет сам дёрнуть API и сверить. Просто не забудьте
попросить. Подробности и готовые проверки — в
[06. Грабли и этика](../06-pitfalls/README.md).

## 5. Сначала план, потом исполнение

Прежде чем агент тронет файлы, он должен сказать, что собирается сделать. Это
не формальность: половина ошибок ловится на стадии плана, когда цена
исправления — одна реплика, а не откат десяти файлов.

В Claude Code это режим `plan` (`claude --permission-mode plan`, или Shift+Tab
в сессии): агент читает и думает, но не пишет, пока вы не утвердите план.
В Codex тот же эффект даёт запрет на запись до подтверждения. См.
[режимы разрешений](https://code.claude.com/docs/en/permission-modes).

Дешёвый приём для больших задач: попросить план в файл — `PLAN.md` — и правьте
его руками. Правки в файле агент увидит, правки в чате забудет.

## 6. Маленькие шаги и git

Git — не бюрократия, а кнопка «отменить» для всего проекта сразу и способ
увидеть, что именно агент натворил.

- Работайте в ветке, коммитьте часто, коммиты маленькие и осмысленные.
- Просматривайте `git diff` перед каждым коммитом. Всегда.
- Не давайте агенту `push`. Публикация — решение человека.
- Одна задача — один коммит. «Агент переписал полстатьи» — это не задача.

Тот же принцип внутри сессии: просите одно изменение за раз. «Перепиши раздел
Methods» — плохо. «В `methods.tex` вынеси описание предобработки в отдельный
подраздел, текст не меняй» — хорошо.

## Что прочитать

Первоисточники, не пересказы. Всё на английском, но читается за вечер.

- [Building effective agents](https://www.anthropic.com/engineering/building-effective-agents) —
  базовая статья Anthropic о том, из чего вообще складывается агент и когда он
  не нужен. Начните с неё.
- [Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) —
  почему «дать побольше контекста» не работает и что делать вместо.
- [Claude Code best practices](https://www.anthropic.com/engineering/claude-code-best-practices) —
  практики работы: планирование, итерации, проверка.
- [Best practices (Codex)](https://learn.chatgpt.com/guides/best-practices) —
  то же самое со стороны OpenAI.
- [How Claude Code works](https://code.claude.com/docs/en/how-claude-code-works) —
  что такое агентный цикл и какие у агента инструменты.
- [Explore the context window](https://code.claude.com/docs/en/context-window) —
  интерактивный разбор того, чем заполняется окно контекста и сколько стоит
  каждое чтение файла.
