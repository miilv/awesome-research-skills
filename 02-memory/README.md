# 02. Память проекта

[← к оглавлению](../README.md)

**Это самый важный раздел.** Разница между «агент бесполезен» и «агент —
полноценный соавтор» почти всегда сводится к тому, написан ли в проекте
нормальный файл памяти.

Каждая сессия агента начинается с чистого листа. Он не помнит вчерашний
разговор, ваши поправки, договорённости с научруком и то, что колонка `subj_id`
в одном датасете значит не то же, что в другом. Единственный способ перенести
знание через сессии — записать его в файл, который агент читает автоматически.

---

## 1. `CLAUDE.md` и `AGENTS.md`

Два имени одного и того же: текстовый файл в корне проекта, который агент
подгружает в начале каждой сессии.

| Файл | Кто читает |
|---|---|
| `AGENTS.md` | Codex; Claude Code тоже умеет его читать |
| `CLAUDE.md` | Claude Code |

Если вы работаете и тем и другим — держите один `AGENTS.md`, а `CLAUDE.md`
сделайте симлинком или тонкой обёрткой на него. Два расходящихся файла хуже,
чем один неидеальный.

- `AGENTS.md` как открытый формат: [agents.md](https://agents.md/)
- Как его читает Codex (порядок, вложенность, лимит 32 KiB):
  [Custom instructions with AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)
- Как устроена память в Claude Code:
  [How Claude remembers your project](https://code.claude.com/docs/en/memory)

### Где лежат файлы

Порядок — от общего к частному; более частное перекрывает более общее.

| Уровень | Claude Code | Codex | Для чего |
|---|---|---|---|
| Личный, для всех проектов | `~/.claude/CLAUDE.md` | `~/.codex/AGENTS.md` | Ваши привычки: язык ответов, любимые инструменты |
| Проект (в git) | `./CLAUDE.md` или `./.claude/CLAUDE.md` | `./AGENTS.md` | Правила проекта — разделяются с соавторами |
| Личное по проекту (вне git) | `./CLAUDE.local.md` | — | Локальные пути, тестовые данные |
| Подкаталог | `subdir/CLAUDE.md` | `subdir/AGENTS.md` | Правила для конкретной части проекта |

Проектный файл коммитится. Личный — нет: добавьте `CLAUDE.local.md` в
`.gitignore`.

### Что писать

Правило: **сюда идёт то, что вы объясняете агенту повторно.** Если вы второй
раз печатаете одну и ту же поправку — её место в файле памяти, а не в чате.

Что должно быть в исследовательском проекте:

1. **Что это за работа.** Две-три строки: предмет, метод, куда подаёмся.
   Без этого агент будет писать «в целом правильно», но не по делу.
2. **Команды.** Как поставить окружение, как запустить анализ, как собрать PDF.
   Дословно, чтобы можно было скопировать.
   ```
   uv sync                    # окружение
   uv run python -m analysis  # пересчёт результатов
   latexmk -pdf paper/main.tex
   ```
3. **Карта репозитория.** Где данные, где код, где текст, что куда пишется.
4. **Договорённости по тексту.** Стиль (кто «мы», времена), стиль ссылок
   (`\citep` / `\citet`), какой `.bib` источник истины, правило про цифры.
5. **Запреты.** Самое ценное. См. ниже.
6. **Как проверять.** Чем убедиться, что изменение не сломало сборку.

### Чего писать не надо

- **Того, что агент выведет сам из кода.** Список файлов, сигнатуры функций,
  «проект на Python». Это шум, который стареет.
- **Длинных инструкций на один раз.** Если это процедура на десять шагов —
  это [скилл](../03-agent-basics/README.md#скиллы), а не память.
  Память грузится всегда и стоит контекста; скилл — только когда нужен.
- **Общих благих пожеланий.** «Пиши хороший код», «будь аккуратен» — ноль
  эффекта. Только проверяемые формулировки:
  «Форматировать правильно» → «Отступ 4 пробела, строки ≤ 100 символов».
  «Тестируй изменения» → «После правки `analysis/` запускать `pytest -q`».
- **Секретов.** Ни токенов, ни паролей, ни путей к чужим персональным данным.
  Файл лежит в git и уходит вместе с репозиторием.
- **Противоречий.** Если два правила конфликтуют, агент выберет одно наугад.
  Перечитывайте файл раз в пару месяцев.

### Сколько писать

Короче, чем хочется. Ориентир из документации Claude Code — **до ~200 строк**
на файл: длинные файлы съедают контекст и хуже соблюдаются. Всё, что нужно
только для части проекта, выносите:

- в `CLAUDE.md` / `AGENTS.md` подкаталога — подгрузится, когда агент туда
  полезет;
- в `.claude/rules/` с привязкой к путям — правило для `*.tex` не будет висеть
  в контексте, пока вы правите Python.

### Как начать

Не пишите с нуля. В Claude Code есть `/init`: агент осмотрит репозиторий и
предложит стартовый файл. Дальше правьте руками — дописывайте то, чего он не
мог узнать сам: договорённости с соавторами, требования журнала, историю
решений.

Шаблоны под исследовательский проект лежат здесь:
[`templates/CLAUDE.md.example`](../templates/CLAUDE.md.example) и
[`templates/AGENTS.md.example`](../templates/AGENTS.md.example).

### Автопамять

Claude Code умеет вести собственные заметки: подмечает ваши поправки и
предпочтения и пишет их сам, отдельно от `CLAUDE.md`. Это дополнение, а не
замена: `CLAUDE.md` пишете вы и он про правила, автопамять пишет агент и она
про ваши привычки. Настройка — в том же
[разделе документации](https://code.claude.com/docs/en/memory).

У Codex есть свой механизм переноса контекста между сессиями:
[Memories](https://learn.chatgpt.com/docs/customization/memories).

## 2. Журнал решений

`CLAUDE.md` отвечает на вопрос «как здесь принято». Журнал решений отвечает на
вопрос «почему мы так сделали» — и это то, что пропадает первым.

Почему выбрали mixed-effects, а не ANOVA. Почему выбросили 12 испытуемых.
Почему порог 0.05, а не FDR. Через полгода на ревью вас об этом спросят, и
вспоминать будет нечего.

Формат: один markdown-файл на решение в `docs/decisions/`, нумерация
сквозная, файлы не редактируются задним числом — решение отменяется новым
решением.

```
docs/decisions/
├── 0001-mixed-effects-instead-of-anova.md
├── 0002-exclude-subjects-with-motion-artifacts.md
└── 0003-switch-preprocessing-to-fmriprep-24.md
```

Шаблон: [`templates/decisions/0001-example.md`](../templates/decisions/0001-example.md).

Как это работает с агентом:

- В `CLAUDE.md` одна строка: «Методологические решения — в `docs/decisions/`.
  Перед изменением анализа прочитай относящиеся к нему».
- Новое решение принято в сессии — просите агента сразу оформить файл. Это
  тридцать секунд, и через полгода они окупятся.
- На rebuttal журнал решений превращается в готовые ответы рецензентам.

## 3. Заметки в markdown

Всё, что вы хотите, чтобы агент знал, должно быть текстом в репозитории. Не в
голове, не в переписке, не в Notion.

```
notes/
├── literature/          # по одной заметке на прочитанную статью
├── meetings/            # что решили с соавторами
└── open-questions.md    # что непонятно и что проверить
```

Заметка по статье — минимум: ключ цитирования, DOI, что сделали, на какой
выборке, к чему это у нас, и ваша оценка. Агент потом соберёт из этих заметок
черновик related work — и в нём будут только те работы, которые вы реально
читали. Это, кстати, и есть главная защита от выдуманных ссылок:
[см. 06](../06-pitfalls/README.md).

## 4. Лог экспериментов

Прогон без записи параметров — потерянный прогон. Минимальная дисциплина:
каждый запуск оставляет запись, по которой его можно повторить.

- одна строка в `experiments/log.md` или запись в CSV;
- обязательные поля: дата, git-хэш кода, конфиг, данные (версия/хэш), команда,
  результат, вывод;
- артефакты — в `results/<дата>-<короткое-имя>/`.

Шаблон: [`templates/experiments/EXPERIMENT.md`](../templates/experiments/EXPERIMENT.md).

Это ровно тот формат, который агент умеет заполнять сам: попросите его после
каждого прогона дописывать строку в лог. Он знает и git-хэш, и команду, которую
запускал.

## 5. Структура репозитория

Агент работает тем лучше, чем предсказуемее разложен проект. Готовая схема с
пояснениями, что куда: [`templates/repo-structure.md`](../templates/repo-structure.md).

Коротко:

```
paper/       текст статьи (LaTeX/Quarto), .bib
analysis/    код анализа
data/        raw/ (только чтение) и processed/ (генерируется)
results/     таблицы и графики — генерируются, в git не обязательны
notes/       заметки
docs/decisions/  журнал решений
experiments/ лог прогонов
AGENTS.md    память проекта
```

Главное правило: **разделяйте то, что руками, и то, что генерируется.** Всё в
`results/` и `data/processed/` должно пересоздаваться одной командой. Тогда
агенту можно спокойно разрешить туда писать.
