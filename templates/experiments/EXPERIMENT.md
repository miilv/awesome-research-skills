# Лог экспериментов

[← к шаблонам](../README.md)

Прогон без записи параметров — потерянный прогон. Ниже два формата: выберите
один и держитесь его.

---

## Формат 1: одна строка в таблице

Для быстрых итераций. Файл `experiments/log.md`:

```markdown
| дата | id | git | конфиг | данные | результат | заметка |
|---|---|---|---|---|---|---|
| 2026-03-14 | e017 | a3f9c21 | configs/base.yaml | v2 (sha 4b1e) | acc .812 ± .009 | baseline |
| 2026-03-14 | e018 | a3f9c21 | configs/base.yaml + lr=3e-4 | v2 (sha 4b1e) | acc .834 ± .007 | лучше, проверить на held-out |
| 2026-03-15 | e019 | 7d2b104 | configs/base.yaml + lr=3e-4 | v2 (sha 4b1e) | acc .829 ± .008 | после рефакторинга — в пределах шума |
```

Обязательные колонки: **дата**, **id**, **git-хэш кода**, **конфиг**,
**версия данных**, **результат**. Без git-хэша запись бесполезна.

Агент умеет заполнять это сам — он знает и хэш, и команду, которую запускал.
Впишите в `AGENTS.md`: «После каждого прогона дописывай строку в
`experiments/log.md`».

---

## Формат 2: файл на прогон

Когда прогоны тяжёлые и их немного. Файл
`experiments/e018-lr-sweep/README.md`:

````markdown
# e018 — подбор learning rate

- **Дата:** 2026-03-14
- **Код:** a3f9c21 (`git log -1 --format=%H`)
- **Данные:** `data/processed/v2`, sha256 `4b1e…`
- **Окружение:** `uv.lock` на момент a3f9c21
- **Железо:** 1× A100 40GB, 3 ч 20 мин

## Зачем

Проверяем, не занижен ли lr=1e-4 из базовой конфигурации.

## Как запускалось

```bash
uv run python -m analysis --config configs/base.yaml \
  --override lr=3e-4 --seed 0,1,2,3,4
```

## Результат

| seed | acc | f1 |
|---|---|---|
| 0 | .831 | .804 |
| 1 | .838 | .811 |
| 2 | .829 | .802 |
| 3 | .841 | .815 |
| 4 | .831 | .806 |

Среднее: acc .834 ± .007, f1 .808 ± .005.

Артефакты: `results/e018/`

## Вывод

lr=3e-4 лучше базового на ~2.2 п.п. по acc. Разница больше разброса по seed.
Переносим в базовую конфигурацию — см. `docs/decisions/0004-lr.md`.

## Что не так

Проверено только на валидации. На held-out не смотрели сознательно —
до фиксации всех гиперпараметров.
````

---

## Что фиксировать всегда

- **git-хэш кода** — иначе «результат» не привязан ни к чему;
- **версию данных** — метку или хэш, не «последняя выгрузка»;
- **seed** — все, включая те, что внутри библиотек;
- **точную команду** — копипастом, а не по памяти;
- **куда легли артефакты**.

## Что фиксировать, когда это важно

- версии ключевых библиотек (если не покрыто лок-файлом);
- железо и время выполнения — для оценки стоимости воспроизведения;
- отрицательные результаты. Особенно отрицательные: без них вы через месяц
  повторите тот же прогон.
