# Структура исследовательского репозитория

[← к шаблонам](README.md)

Раскладка, под которую агент работает предсказуемо. Не догма — но чем ближе
ваш проект к чему-то такому, тем меньше придётся объяснять словами.

```
project/
├── AGENTS.md              ← память проекта (и/или CLAUDE.md)
├── README.md              ← для людей: о чём работа, как запустить
├── .gitignore
├── pyproject.toml         ← зависимости
├── uv.lock                ← ЗАФИКСИРОВАННЫЕ версии, коммитится
│
├── data/
│   ├── raw/               ← исходники. ТОЛЬКО ЧТЕНИЕ. Не в git, если тяжёлые
│   ├── processed/         ← генерируется. Не в git
│   └── README.md          ← откуда данные, версия, дата, как получены
│
├── analysis/
│   ├── __main__.py        ← одна точка входа: пересчитать всё
│   ├── preprocess.py
│   ├── models.py
│   └── figures/           ← по файлу на рисунок
│       ├── fig1_design.py
│       └── fig2_accuracy.py
│
├── results/               ← генерируется: таблицы, рисунки, numbers.tex
│
├── paper/
│   ├── main.tex
│   ├── sections/
│   ├── refs.bib           ← из Zotero через Better BibTeX, руками не править
│   └── figures/           ← симлинки или копии из results/
│
├── notes/
│   ├── literature/        ← по заметке на прочитанную статью
│   ├── meetings/
│   └── open-questions.md
│
├── docs/decisions/        ← журнал решений: почему сделали так
│   ├── 0001-....md
│   └── 0002-....md
│
├── experiments/
│   └── log.md             ← лог прогонов
│
├── reviews/               ← появляется после подачи: рецензии и разбор
│
└── .claude/
    ├── settings.json      ← разрешения и хуки, коммитится
    └── skills/            ← проектные скиллы
```

## Три правила, ради которых всё это

### 1. Ручное отдельно от генерируемого

`data/processed/` и `results/` пересоздаются одной командой из `data/raw/`.
Ничего оттуда не правится руками — никогда, ни разу, даже «быстренько».

Зачем: как только это правило соблюдается, агенту можно безопасно разрешить
писать в эти каталоги без подтверждения. А вам — не бояться, что он что-то
затёр.

### 2. Одна команда пересчитывает всё

```bash
uv run python -m analysis
```

Если для воспроизведения результата нужно «запустить вот это, потом вон то,
потом поправить путь» — воспроизводимости нет, и агент тут не поможет, он
только быстрее наплодит расхождений.

Когда шагов становится больше пяти — переходите на
[Snakemake](https://snakemake.readthedocs.io/).

### 3. `data/raw/` неприкосновенен

Технически: запретите запись туда
[хуком](../03-agent-basics/README.md#хуки) или правилом в
`.claude/settings.json`. Не просьбой в `AGENTS.md` — просьбу можно
интерпретировать, запрет нельзя.

## Что коммитить, а что нет

| Коммитить | Не коммитить |
|---|---|
| весь код, `AGENTS.md`, `.claude/settings.json` | `data/raw/` (если тяжёлые — держать рядом, описать в `data/README.md`) |
| `uv.lock` / `environment.yml` | `data/processed/` |
| `paper/` целиком, включая `refs.bib` | `results/` (если тяжёлые; лёгкие — можно и нужно) |
| `notes/`, `docs/decisions/`, `experiments/log.md` | `CLAUDE.local.md`, `.env`, любые ключи |

Тяжёлые данные и результаты — через Git LFS,
[Zenodo](https://zenodo.org/) или [OSF](https://osf.io/), со ссылкой из
`data/README.md`.

---

## Минимальный вариант

Если проект маленький, не разводите бюрократию. Достаточно:

```
project/
├── AGENTS.md
├── data/raw/
├── analysis/
├── results/
├── paper/
└── notes/literature/
```

Остальное добавляется тогда, когда становится нужно, а не заранее.
